1. INTRODUCTION                                           *icebox-introduction*

Supply-chain attacks against Neovim plugins are a real threat. icebox.nvim
brings a "minimum release age" style mitigation to the ecosystem: a commit
is not adopted until it has been publicly visible for a cooldown period,
giving you time to notice a malicious release and pull it before it reaches
your editor.

The natural place to anchor such a cooldown would be the timestamps inside
a Git commit, but every one of them (author date, committer date,
annotated-tag date, ref mtimes) is written by whoever produced the commit.
An attacker who controls the upstream can set them to anything, so they
cannot mark a trustworthy publication time.

icebox.nvim instead measures elapsed time from the point at which your
local machine first observed each commit hash. That clock is the one thing
an attacker cannot rewind. The cooldown is exposed as a simple function
that returns a commit hash once its local observation has aged past a
configurable threshold; hand that hash to your plugin manager's existing
commit-pinning feature and you are done.

==============================================================================
2. REQUIREMENTS                                           *icebox-requirements*

- Neovim >= 0.10
- `git` available on PATH

==============================================================================
3. INSTALLATION                                           *icebox-installation*

Clone the repository manually. icebox.nvim must be on the runtimepath before
your plugin manager runs, so it cannot be managed by the plugin manager
itself. >bash
  git clone https://github.com/minoritea/icebox.nvim \
    ~/.local/share/nvim/icebox.nvim
<
Then prepend it to the runtimepath at the top of `init.lua`, before your
plugin manager is loaded: >lua
  vim.opt.rtp:prepend(vim.fn.stdpath("data") .. "/icebox.nvim")
<

Windows ~
                                                              *icebox-windows*
Windows is supported on an experimental basis. Where this document
refers to `$XDG_DATA_HOME` or `$XDG_CACHE_HOME`, read them as
`stdpath("data")` and `stdpath("cache")` respectively — icebox falls
back to these when the corresponding XDG environment variables are not
set, which is the typical case on Windows.

==============================================================================
4. HOW IT WORKS                                        *icebox-how-it-works*

icebox.nvim keeps a store file that records each commit hash it has seen
along with the time it was first observed. Every |icebox.thaw()| call
schedules a background job that refreshes this store, so a call returns
immediately with a commit drawn from whatever the previous run recorded.

The commit is chosen as follows:

    1. Restrict the candidate commits by the branch/version option:
       - `branch`  → commits on that branch (newest-first history)
       - `version` → tags whose semver matches the range
    2. Among those candidates, pick the newest one that has cooled down
       (`fetched_at + cooldown_days <= now`).

If `trusted_commit` is set, it is returned instead when both of the
following hold:

    1. `trusted_commit` is among the candidates from step 1.
    2. `trusted_commit` is newer than the commit picked in step 2.

If no commit qualifies, |icebox.ZERO_HASH| is returned.

==============================================================================
5. SETUP                                                        *icebox-setup*

|icebox.setup()| is optional. To override the global icebox
configuration (whose defaults are documented in |icebox-options|), pass
a table to `setup()`. After the call, the effective configuration is
the defaults merged with the fields you supplied.

Example: >lua
  require("icebox").setup({
    cooldown_days      = 14,
    trust_on_first_use = false,
  })
<
==============================================================================
6. API                                                            *icebox-api*

------------------------------------------------------------------------------
icebox.setup({opts})                                          *icebox.setup()*

`setup()` is currently used solely to override the default configuration.
The override is performed by merging {opts} into the built-in defaults,
so any previous call's settings are ignored.

Parameters:
  {opts}  (table|nil) Configuration table. See below.

Options ~
                                                              *icebox-options*
Options accepted by `setup()`:

cooldown_days                                          *icebox-opt-cooldown*
  Type:    number
  Default: 7

  Number of days a commit must be known to icebox.nvim before it is returned
  by |icebox.thaw()|. Set to `0` to disable cooldown entirely (every known
  commit is immediately eligible).

trust_on_first_use                            *icebox-opt-trust-on-first-use*
  Type:    boolean
  Default: false

  Controls behaviour on the very first call for a URL (when the local store
  is empty).

  false  Return |icebox.ZERO_HASH| and schedule a background fetch. On the
         next Neovim startup the fetched data will be available and the
         cooldown clock starts. `trusted_commit`, if supplied, is NOT
         consulted in this path — the first observation is always withheld.

  true   Bypass the initial-observation guard once. Specifically:
           - If `trusted_commit` is set, it is returned as-is (no
             candidate-set check, since no candidate set exists yet), and
             a background fetch is scheduled to populate the store.
           - Otherwise, a synchronous git fetch is performed and the
             newest matching commit is returned immediately with the
             cooldown bypassed for that first result only.
         Subsequent calls (once the store has records) go through the normal
         cooldown path and `trusted_commit` reverts to its usual
         candidate-set-scoped semantics — see
         |icebox-thaw-opt-trusted-commit|.

         Trade-off: enabling this leaves the initial-install-day window
         unprotected. If the upstream is already compromised when icebox
         first observes it, that state will be adopted immediately. Prefer
         the default unless you know the upstream is currently in a state
         you would sign off on manually.

branch_commits_per_fetch                *icebox-opt-branch-commits-per-fetch*
  Type:    number (integer >= 1)
  Default: 500

  Maximum number of branch commits pulled per fetch. Passed to `git log -n`
  when |icebox.thaw()| performs a branch fetch (both sync and async paths).

  Only the newest N commits (in first-parent order) become candidates for
  branch resolution. Commits older than this window are simply not returned
  by that fetch — a later fetch that surfaces them will add them to the
  store. Existing entries in `fetched_at` are preserved across fetches, so
  the original observation timestamp of a commit is never overwritten.

  Trade-offs:
  - Smaller values keep the store JSON compact and speed up resolution on
    long-lived branches.
  - Larger values increase the chance that an older `trusted_commit` is
    still in the candidate set (see |icebox-thaw-opt-trusted-commit|).

------------------------------------------------------------------------------
icebox.thaw({url}, {opts})                                    *icebox.thaw()*

Given a repository URL, returns the newest cooled commit hash. GitHub
shorthand (`owner/repo`) is also accepted. |icebox.ZERO_HASH| is returned
when no cooled commit is available yet or when an error occurs.

Callable in exactly one of these three forms; any other call shape is a
parse error (WARN + |icebox.ZERO_HASH|):
  - `thaw(url)`         — positional URL string
  - `thaw(url, opts)`   — positional URL string + opts table
  - `thaw(opts)`        — single opts table (URL from opts.url or opts.clone_path)

URL sources are MUTUALLY EXCLUSIVE. Exactly one of the following must be
provided:
    {url} argument   — Git URL as a string
    opts.url         — same, but inside the opts table
    opts.clone_path  — URL is resolved from the clone's `origin` remote
If more than one is specified, or none is specified, |icebox.thaw()| emits a
|vim.notify| WARN and returns |icebox.ZERO_HASH|.

Parameters:
  {url}   (string) Any valid Git URL, or a GitHub shorthand (`owner/repo`).
          Local file paths must be absolute.

  {opts}  (table) See |icebox-thaw-opts|. At most one of `branch` or
          `version` may be specified.

          When neither `branch` nor `version` is specified, icebox.nvim
          treats the call as if the latest semver tag were requested when
          the repository has any semver tags, or as if the default branch
          were requested otherwise.

Return:   (string) A 40-character commit hash, or |icebox.ZERO_HASH|.

thaw() opts ~
                                                            *icebox-thaw-opts*
The second argument to |icebox.thaw()| is an optional table. At most one of
`branch` or `version` may be set.

branch                                              *icebox-thaw-opt-branch*
  Type: string
  Set this to restrict cooled-commit selection to the given branch's
  history. >lua
    icebox.thaw(url, { branch = "main" })
<
version                                            *icebox-thaw-opt-version*
  Type: string
  Set this to restrict cooled-commit selection to tags matching the given
  semver range. Supported operators: `^`, `~`, `>=`, `>`, `<=`, `<`, and
  exact version strings. A leading `v` on tag names is handled
  automatically; pre-release suffixes such as `1.2.3-alpha` are supported
  (a release tag ranks higher than the same version with a suffix). >lua
    icebox.thaw(url, { version = "^1.0.0" })
    icebox.thaw(url, { version = ">=2.0.0" })
    icebox.thaw(url, { version = "~1.4.0" })
<
normalize                                        *icebox-thaw-opt-normalize*
  Type: function
  Custom tag normalization function used when `version` is set. When
  provided, replaces the default normalization logic (which handles
  `vX.Y.Z` / `X.Y.Z` mixing and pre-release suffixes).

  The function receives a list of raw tag name strings and must return a
  map of the form: >lua
    { [tag_string] = { major, minor, patch [, suffix] }, ... }
<
  Non-semver tags should be excluded from the returned map (it may have
  fewer entries than the input list, or be empty).

  Example — accept two-segment tags like `1.4` by defaulting patch to 0: >lua
    icebox.thaw(url, {
      version   = ">=1.0.0",
      normalize = function(tags)
        local out = {}
        for _, t in ipairs(tags) do
          local maj, min, pat = t:match("^(%d+)%.(%d+)%.?(%d*)$")
          if maj then
            out[t] = { tonumber(maj), tonumber(min), tonumber(pat) or 0 }
          end
        end
        return out
      end,
    })
<
trusted_commit                              *icebox-thaw-opt-trusted-commit*
  Type: string (40-char hex)
  Set this to bypass the cooldown for a specific commit hash you have
  already verified as safe. In the normal (populated-store) path, the
  bypass applies only when the hash belongs to the candidate set implied
  by `branch` or `version` — a `trusted_commit` outside that set is
  ignored.

  When both a cooled commit and `trusted_commit` are available in the
  candidate set, the newer of the two is returned. "Newer" is defined
  per option:
    - `branch`  : smaller index in the newest-first history array
    - `version` : higher semver order
  Commit-object timestamps are never consulted.

  Empty-store exception: on the very first call for a URL, no candidate
  set exists yet. With `trust_on_first_use = false` (default),
  `trusted_commit` is IGNORED and |icebox.ZERO_HASH| is returned. With
  `trust_on_first_use = true`, `trusted_commit` is returned as-is
  without a candidate-set check. See |icebox-opt-trust-on-first-use|.

  Example: >lua
    icebox.thaw(url, {
      branch         = "main",
      trusted_commit = "a1b2c3...",  -- must be a commit on `main`
    })
<
cooldown_days                                *icebox-thaw-opt-cooldown-days*
  Type: number
  Overrides |icebox-opt-cooldown| for this call only. See there for type,
  default, and semantics.

trust_on_first_use                      *icebox-thaw-opt-trust-on-first-use*
  Type: boolean
  Overrides |icebox-opt-trust-on-first-use| for this call only. See there
  for type, default, and semantics.

branch_commits_per_fetch          *icebox-thaw-opt-branch-commits-per-fetch*
  Type: number
  Overrides |icebox-opt-branch-commits-per-fetch| for this call only. See
  there for type, default, and semantics.

url                                                    *icebox-thaw-opt-url*
  Type: string
  Same as the positional {url} argument. Either form is accepted, but
  they are mutually exclusive (`clone_path` is also mutually exclusive
  with both). >lua
    icebox.thaw({
      url    = "stevearc/oil.nvim",
      branch = "main",
    })
<

clone_path                                      *icebox-thaw-opt-clone-path*
  Type: string
  Set this to reuse an EXISTING local clone maintained by another tool
  (typically your plugin manager) instead of icebox's own cache under
  `$XDG_CACHE_HOME/icebox.nvim/clones/`. Only `branch` history reads
  from the local clone; `version` resolution still uses `git ls-remote`
  against the upstream.

  The upstream URL is taken from the clone's `origin` remote and used
  as the store key and fetch target. Mutually exclusive with the
  positional {url} and `opts.url`; specifying more than one source
  emits a WARN and returns |icebox.ZERO_HASH|.

  icebox does not own this clone. It never creates the directory,
  initializes a repo there, or clones into it. The path must already
  exist, be a valid git repository, and have an `origin` remote; if
  any of these conditions fails, |icebox.thaw()| emits a WARN and
  returns |icebox.ZERO_HASH| with no fallback to the icebox cache.
  Paths are normalized via `vim.fs.normalize` (so `~`, `..`, and
  redundant slashes are resolved).

  icebox's writes to the clone are limited to `git fetch --no-tags`
  and reads via `git log --first-parent FETCH_HEAD`. Local refs
  (`refs/heads/*`, `refs/tags/*`, `refs/remotes/*`, `HEAD`), the
  working tree, and `.git/config` are never modified.

  Race with your plugin manager: git's own ref-locking prevents
  corruption, but if both processes fetch at the exact same moment
  one of the two `FETCH_HEAD` writes will be lost. In practice this
  is rare and self-healing on the next invocation.

  Example: >lua
    icebox.thaw({
      clone_path = vim.fn.stdpath("data") .. "/lazy/repo",
      branch     = "main",
    })
<

------------------------------------------------------------------------------
icebox.ZERO_HASH                                            *icebox.ZERO_HASH*

The value returned when no cooled commit is available or an error occurs.
It is an all-zero Git hash string, which Git treats as an invalid commit
hash. When combining with a plugin manager, the recommended usage is to
pass it through unchanged and let the plugin manager fail on it.

------------------------------------------------------------------------------
icebox.lazy.cooldown({spec})                          *icebox.lazy.cooldown()*

Helper for lazy.nvim. Given a lazy plugin spec, if `spec.icebox_options`
is set, it calls `thaw(spec[1] or spec.url or spec.dir, spec.icebox_options)`
and pins the returned commit onto the spec before returning it.

Example: >lua
  local cooldown = require("icebox.lazy").cooldown

  require("lazy").setup(vim.tbl_map(cooldown, {
    { "ibhagwan/fzf-lua",     icebox_options = { branch = "main" } },
    { "stevearc/oil.nvim",    icebox_options = { version = "^1.0.0" } },
    { "github/copilot.vim" }, -- no icebox_options → passed through
  }))
<
